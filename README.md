# TripTie

## Краткое описание
Проект TripTie представляет собой веб-приложение для планирования путешествий, состоящее из трех основных компонентов:
- **PostgreSQL** - база данных для хранения данных приложения
- **Python Backend** - серверная часть на FastAPI/Django
- **Next.js Frontend** - клиентская часть на React с TypeScript

## Требования для запуска
- Docker 20.10+ и Docker Compose 2.0+
- 4 ГБ свободной оперативной памяти
- 2 ГБ свободного места на диске

## Быстрый старт

### 1. Запуск приложения
```bash
# Клонирование репозитория (если необходимо)
git clone https://github.com/Evergrove-Vault/TripTie.git
cd TripTie

# Запуск всех сервисов
docker-compose up --build
```

### 2. Доступ к приложению
После успешного запуска приложение будет доступно по адресам:
- **Фронтенд**: http://localhost:3000
- **Бэкенд (API)**: http://localhost:8000
- **База данных**: localhost:5432 (только внутри Docker-сети)

### 3. Остановка приложения
```bash
# Остановка всех контейнеров
docker-compose down

# Остановка с удалением томов (включая данные БД)
docker-compose down -v
```

## Конфигурация сервисов

### База данных (PostgreSQL)
- **Пользователь**: triptie
- **Пароль**: triptie
- **База данных**: triptie
- **Порт**: 5432
- **Данные сохраняются** в Docker volume: `postgres_data`

### Бэкенд (Python)
- **Порт**: 8000
- **Зависит от** работоспособности базы данных
- **Автоматически применяет миграции** через entrypoint.sh

### Фронтенд (Next.js)
- **Порт**: 3000
- **Собирается** с параметром BACKEND_URL
- **Использует API** по адресу http://localhost:8000

## Разработка

### Hot-reload разработка
Приложение настроено для удобной разработки:
- Изменения в коде бэкенда (`./backend/`) применяются автоматически
- Изменения в коде фронтенда требуют перезагрузки страницы
- Данные БД сохраняются между перезапусками

### Пересборка отдельных компонентов
```bash
# Пересборка только бэкенда
docker-compose up --build backend

# Пересборка только фронтенда
docker-compose up --build frontend
```

## Устранение неполадок

### 1. Проблемы с портами
Если порты 3000, 8000 или 5432 заняты:
- Измените порты в `docker-compose.yml`
- Или остановите конфликтующие сервисы

### 2. Очистка Docker
```bash
# Удаление всех неиспользуемых ресурсов
docker system prune -a --volumes

# Просмотр логов конкретного сервиса
docker-compose logs -f backend
```

### 3. Сброс базы данных
```bash
# Полная очистка с удалением данных
docker-compose down -v
docker-compose up --build
```

## Переменные окружения

### Бэкенд
- `DATABASE_URL` - подключение к PostgreSQL

### Фронтенд
- `NEXT_PUBLIC_API_URL` - публичный URL API
- `BACKEND_URL` - внутренний URL API для сборки
